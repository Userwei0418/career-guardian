# Pin 系统架构总览

## 1. 整体架构

系统采用**微服务架构**，由四个独立服务组成：

```
+-------------------------------------------------------------------+
|                          用户访问层                                |
|    浏览器 -> Next.js 前端 (port 3000)                              |
+-----------------------------+-------------------------------------+
                              | HTTP/JSON
+-----------------------------V-------------------------------------+
|                       FastAPI 后端 (port 8000)                    |
|  +------------+ +------------+ +------------+ +------------------+ |
|  | 职位路由   | | 公司路由   | | 分析路由   | | 爬虫管理代理     | |
|  +------------+ +------------+ +------------+ +------------------+ |
|  +------------------------------------------------------------+   |
|  | Redis 缓存层 (TTL分层 + 预热)                               |   |
|  +------------------------------------------------------------+   |
+-----------------------------+-------------------------------------+
                              |
        +---------------------+---------------------+
        |                     |                     |
        V                     V                     V
+--------------+   +--------------------+   +--------------------+
| MySQL 8.0    |   | 爬虫管理服务        |   | 系统监控服务        |
| (业务数据)    |   | (port 8001)         |   | (port 8002)        |
+--------------+   +--------------------+   +--------------------+
                          |
                          V
               +--------------------+
               | Playwright 爬虫     |
               | (dom/api/拦截)     |
               +--------------------+
```

## 2. 服务职责

### 2.1 后端 API 服务 (backend/api/main.py)

- **路由注册**：职位、公司、分析、技能、薪资、城市、聚类、匹配等
- **爬虫管理代理**：转发爬虫相关请求到爬虫管理服务
- **缓存预热**：启动时后台线程每30分钟预热核心接口
- **WebSocket**：`/ws/crawl-status` 实时推送爬虫状态
- **数据入库触发**：`/api/ingest/trigger` 触发 LLM 解析结果入库

### 2.2 爬虫管理服务 (services/crawler_service.py)

- 接收爬虫启动/停止指令
- 管理任务生命周期（pending -> running -> completed/failed）
- 线程池并发执行（最多3个任务）
- 日志实时采集与查询
- 系统指标采集（CPU/内存/磁盘）

### 2.3 系统监控服务 (services/monitor_service.py)

- 每10秒采集系统指标
- 历史数据保留（1小时滚动窗口）
- 异常告警（CPU > 80%, 内存 > 85%, 磁盘 > 90%）
- WebSocket 实时推送

## 4. 数据流向

```
目标网站 -> Playwright爬虫 -> 原始HTML/JSON
                              |
                              V
                    crawl_jobs 表 (raw_html, raw_json)
                              |
                    LLM解析 (parsegpt/)
                              |
                              V
                    crawl_jobs 表 (model_json, status=parsed)
                              |
                    入库流程 (ingest_cjob.py)
                              |
                              V
                    jobs 表 + companies 表 (标准化数据)
                              |
                              V
                    Redis缓存 -> 前端展示
```

## 5. 核心设计原则

1. **数据库驱动**：爬虫配置、任务状态、中间数据均持久化到 MySQL
2. **Pipeline 编排**：抓取 -> 解析 -> 入库 三步可独立执行
3. **缓存分层**：Redis TTL 按接口计算量差异化设定 (180s ~ 3600s)
4. **智能命中**：仅缓存默认首页请求，避免缓存爆炸
5. **降级兜底**：分析接口优先读缓存表，不可用时降级到实时查询

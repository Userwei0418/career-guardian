# 腾讯云 OCR 配置与费用安全边界

> 文档状态：已启用、完成真实调用及长截图登录态批次，业务质量继续验收
> 最后更新：2026-08-25
> 当前能力事实：代码已接入腾讯云 OCR 官方 Python 产品 SDK、月度软上限、单批保护、调用审计、Tesseract 降级、逐片详情、坐标配行和候选来源框选；密钥只保存在本机后端 `.env`。真实批次 #24 已完成 14/14 个切片、99 条候选和 99/99 用户确认入账。接入早期的 47 次调用与错误批次 #18 只保留为历史故障证据；实时用量必须查询“管理后台 → 服务配置”和腾讯云控制台，不能沿用文档中的历史累计数。

## 1. 采用范围

收支守护不再计划引入 PaddleOCR。目标方案是：

```text
账单长截图
  → 职护本机校验、缩放和重叠切片
  → 腾讯云 GeneralAccurateOCR 逐片识别文字、坐标和置信度
  → 职护程序按坐标组合日期、时间、商户、金额和方向
  → 疑难项复用职护现有 AI 做解释
  → 用户确认后才进入正式账本
```

腾讯云 OCR 只替代基础文字检测与识别，不拥有记账、分类确认、重复合并或正式入账权限。现有 AI 也不能把候选静默写入账本。

## 1.1 为什么继续切片而不是整图一次调用

腾讯官方当前只明确要求高精度接口的图片/PDF经 Base64 编码后不超过 10MB，并建议分辨率至少 600×800；没有据此承诺极端长图一定完整识别。真实 `794×18578` 原图约 2.51MB，Base64 后约 3.35MB，虽满足大小限制，但一次整图实测只返回 5 个日期标题，10 个抽样商家命中 4 个，平均置信度约 84.9%；确定性规则仅形成 24 个稳定候选，并留下 96 个低置信锚点。14 片方案调用更多，但交易和商家覆盖明显更完整。

当前策略是质量优先保留重叠切片。后续可以对约 7 个较大自适应切片做独立 A/B，验收指标必须同时覆盖日期标题、金额、商家、交易行召回、跨片重复和错位率；只减少调用次数但降低商家召回不得上线。

## 2. 免费额度和费用边界

腾讯云 2026-08-03 更新的官方说明是：通用文字识别等部分服务开通后共享每月 1,000 次免费调用额度，资源包每月 1 日发放、只在当月有效；同一共享资源包中的多个接口会共同消耗这 1,000 次。账号连续一年未使用 OCR 时，腾讯云可能暂停月初发放，恢复调用后再补发。该额度、接口归属和价格都可能变化，实际以当前账号控制台的资源包和计费页面为准，不能只凭职护页面中的配置值判断剩余额度。

这里的“一次”是一次 `GeneralAccurateOCR` API 请求，不是一张用户上传的完整长截图：

- 一张长截图拆为 14 个识别切片，正常完成至少消耗约 14 次；
- 单片失败重试可能再次消耗调用次数；
- 多张连续截图会按合计切片数消耗；
- 识别批次恢复应复用已经保存的 OCR 结果，不能重复调用；
- 同一原图和同一解析器版本命中幂等记录时不能重新调用。

应用侧已完成：

- 单批最大调用次数保护；
- 900 次月度软停止阈值和 100 次安全预留；
- 已完成切片结果复用与调用审计；
- 云端不可用时按配置降级到 Tesseract/人工核对。

腾讯云账号侧仍需持续确认：

1. 不购买预付费资源包；
2. 不开通后付费；
3. 先只使用免费资源包；
4. 在腾讯云控制台确认“免费资源包耗尽后停止服务”，不能默认自动扣费；
5. 配置用量告警并定期核对资源包、后付费状态和真实账单；应用软阈值不是腾讯云侧的硬计费熔断器。

关闭后付费后，免费额度耗尽会使云 OCR 不可用。职护应明确提示并降级到本机 Tesseract/人工核对，不能因此丢失候选或自动购买额度。

## 3. 腾讯云控制台配置步骤

### 3.1 开通 OCR

1. 注册或登录腾讯云账号并完成实名认证；
2. 进入[腾讯云文字识别控制台](https://console.cloud.tencent.com/ocr)；
3. 开通“通用文字识别（高精度版）”；
4. 在资源包管理中确认已到账的免费额度、有效期和剩余次数；
5. 在计费设置中确认后付费处于关闭状态。

不要购买“文档抽取 Agent”“表格识别 V3”“商户门头照识别”等其他服务。当前职护只使用 `GeneralAccurateOCR`。

### 3.2 创建最小权限调用身份

不要给职护使用腾讯云主账号永久密钥。推荐在访问管理 CAM 中创建一个仅供职护后端调用的子用户或服务身份，并只授予 `GeneralAccurateOCR` 操作权限。

自定义策略目标：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "name/ocr:GeneralAccurateOCR"
      ],
      "resource": [
        "*"
      ]
    }
  ]
}
```

腾讯云 CAM 的 API 操作使用 `name/` 前缀；当前把 `GeneralAccurateOCR` 标为操作级授权，资源为 `*`，并支持 IP 限制。正式部署有稳定出口 IP 时，应进一步限制来源 IP；本地开发阶段可先不限制，完成验证后再收紧。

如果控制台不接受上述自定义策略，可临时给专用子用户关联 `QcloudOCRFullAccess` 完成联调，但不能给它支付、财务、CAM 管理或其他云产品权限；联调结束后应改回单接口权限。

官方参考：

- [腾讯云 OCR 的 CAM 授权粒度](https://intl.cloud.tencent.com/zh/document/product/598/60621)
- [腾讯云 OCR 账号和子用户说明](https://cloud.tencent.com/document/faq/866/36470)
- [腾讯云 CAM 策略语法](https://www.tencentcloud.com/zh/document/product/1131/44511)

### 3.3 创建密钥

在专用子用户下创建 API 密钥，取得：

- `SecretId`
- `SecretKey`

安全要求：

- 不要把密钥发送到聊天、Issue、截图或日志；
- 不要写入前端 `.env.local` 或任何 `NEXT_PUBLIC_*` 变量；
- 不要提交后端 `.env`；
- SecretKey 通常只在创建时完整展示，应保存在系统密钥管理器或部署平台 Secret 中；
- 密钥泄露时立即在 CAM 禁用并轮换。

## 4. 职护后端目标配置

职护后端已读取以下环境变量：

```dotenv
TENCENT_OCR_ENABLED=true
TENCENT_OCR_SECRET_ID=在专用子用户下创建的SecretId
TENCENT_OCR_SECRET_KEY=在专用子用户下创建的SecretKey
TENCENT_OCR_REGION=ap-guangzhou
TENCENT_OCR_REQUEST_TIMEOUT_SECONDS=35
TENCENT_OCR_MAX_CALLS_PER_BATCH=40
TENCENT_OCR_MONTHLY_INCLUDED_QUOTA=1000
TENCENT_OCR_MONTHLY_SOFT_LIMIT=900
TENCENT_OCR_FALLBACK_TO_TESSERACT=true
```

这些变量已进入运行代码，本机已完成“密钥保存、代码接入、服务重启、真实调用”四层验证。其他部署环境仍必须分别完成这四项，不能因为代码已经合并就推断对应服务器已配置密钥或已开通服务。

`TENCENT_OCR_MONTHLY_INCLUDED_QUOTA=1000` 表示当前账号确认的月度免费资源额度，只用于管理页面展示；`TENCENT_OCR_MONTHLY_SOFT_LIMIT=900` 才是应用主动停止云端调用的保护阈值。两者必须分开展示：1000 不是应用可无保护耗尽的目标，900 也不是腾讯云免费额度。默认预留 100 次用于并发、重试和控制台统计延迟；达到软阈值后按配置降级 Tesseract，不自动进入后付费。

当前分支使用腾讯官方按产品拆分的轻量 SDK，不安装全产品 SDK：

```text
tencentcloud-sdk-python-common==3.1.132
tencentcloud-sdk-python-ocr==3.1.132
```

本地密钥放在：

```text
zhihu/zhihu-backend/.env
```

正式环境应使用部署平台 Secret/环境变量注入，不把生产密钥保存在仓库文件、镜像层或备份文档中。

## 5. 图片出站和用户披露

启用腾讯云 OCR 后，图片不再是“原图不出站”：

- 整张原始长截图仍不作为附件长期保存；
- 职护会在本机完成缩放和切片；
- 识别所需的派生切片会发送给腾讯云 OCR；
- 腾讯返回文字、坐标、置信度和请求 ID；
- 职护保存必要切片与 OCR 结果用于候选续办和证据定位；
- 发送腾讯前不可能先靠 OCR 完成图中文字脱敏，因此不能沿用“只发送脱敏文字”的旧文案。

前端在用户首次使用云 OCR 前必须明确展示处理方、发送内容、用途、确认后才入账以及原文件留存边界，并由用户主动勾选确认。当前登录态链路已有该披露，后续修改入口、供应商或留存策略时必须重新验收，不能静默扩大出站范围。

## 6. 接入后的验收步骤

1. 使用不含真实财务信息的合成图片调用一次 `GeneralAccurateOCR`；
2. 确认返回 `RequestId`、文本行、坐标和置信度，日志不记录图片 Base64、OCR 全文、SecretId 或 SecretKey；
3. 在腾讯云控制台确认调用次数只增加预期数量且没有付费账单；
4. 用同一张真实长截图分别对照旧 Tesseract 和腾讯 OCR 的交易召回、商户名、日期继承和跨片重复；
5. 验证关闭模态框后恢复批次不会重复调用已完成切片；
6. 验证免费额度不可用、超时、限流和认证失败时保留候选并明确降级；
7. 完成桌面和手机登录态的隐私披露、进度、失败重试和候选定位验收；
8. 当前已可称为“腾讯云 OCR 已接入”；只有错误恢复、重试、更多真实账单样式、手机端、费用告警和逐笔准确率均达到验收标准后，才能称为“完整业务质量验收通过”或默认向全部正式用户开放。

## 7. 停用和密钥轮换

紧急停用顺序：

1. 将 `TENCENT_OCR_ENABLED=false`；
2. 重启职护后端；
3. 在腾讯 CAM 禁用对应 SecretId；
4. 只读核对腾讯云调用量和账单；
5. 保留已生成候选，不删除或重复识别用户批次；
6. 需要恢复时创建新密钥，不重新启用已泄露密钥。

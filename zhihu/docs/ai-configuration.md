# 职护服务配置说明

- 生效日期：2026-08-25
- 管理入口：`管理后台 → 服务配置`
- 代码入口：`app/api/routes/ai_admin.py`、`app/services/ai_configuration_service.py`、`app/services/assistant_service.py`、`app/services/speech_service.py`、`app/services/cashflow_tencent_ocr_service.py`

“服务配置”同时覆盖统一 AI 模型服务和腾讯云 OCR，不再用“AI 配置”概括所有外部能力。AI 模型配置可由管理员页面维护；腾讯 OCR 当前只读展示后端环境变量的运行状态、非敏感参数和调用额度，页面不读取、显示或保存 SecretId/SecretKey。

## 默认配置基线

管理员配置应使用以下 OpenAI 兼容接口基线：

```text
provider=SenseAudio
base_url=https://api.senseaudio.cn/v1
LLM_MODEL=deepseek-v4-flash
TTS_MODEL=senseaudio-tts-1.5-260319
TTS_VOICE_ID=female_0033_b
REALTIME_MODEL=senseaudio-realtime-1.0
REALTIME_VOICE_ID=f_y_0035_c
IMAGE_MODEL=senseaudio-image-2.0-260319
IMAGE_LANDSCAPE_SIZE=1536x864
IMAGE_SQUARE_SIZE=1024x1024
API_KEY=由管理员配置，接口和页面只显示末四位
```

业务后端最终请求 `${base_url}/chat/completions`，使用 `Authorization: Bearer ...` 和 `temperature=0.1`。普通调用默认 30 秒超时；简历结构化解析、目标岗位学习路线和简历微调由于输入较长，使用 60～75 秒超时。Web 同源代理仅对这些明确的长耗时 AI 功能放宽到 90 秒。

## 使用范围

- Offer 文本结构化抽取调用统一 `_call_llm`；AI 不可用时返回空结构，由用户手工填写。
- 岗位 JD—简历分析调用同一配置；AI 不可用、超时或返回非 JSON 时，明确降级为规则核对，不伪装成 AI 结论。
- 简历上传或粘贴后，解析全文保存到 MySQL，并自动发送给管理员配置的 AI 服务，生成学历、经历、项目、技能和亮点等结构化档案。AI 不可用、超时或 JSON 无效时保留原文，并明确降级到本地规则解析。
- 岗位 JD—简历分析仍只在用户选择简历版本并主动点击“加入机会守护”后发起；匹配输入同时包含结构化档案和解析全文，技能标签不作为唯一依据。
- 收藏岗位不会自动调用 AI。用户把岗位设为目标并主动操作后，系统才会用所绑定的简历生成能力差距、阶段学习路线、可验证产出、面试准备和招聘方确认问题。
- 能力路线成功后，前端会自动请求摘要语音，并在标题右侧提供播放/暂停。缓存键由“摘要 + TTS 服务商/模型 + 音色 + 语速、音量、音调、格式等合成参数”共同计算；文字或任一声音参数变化都会生成新缓存，完全一致时重复播放不重复调用 TTS。
- 目标岗位可发起端到端实时语音模拟面试。浏览器通过短期会话票据连接职护后端，后端再携带管理员密钥代理 SenseAudio WebSocket；岗位 JD、绑定简历和能力路线作为每场动态上下文，管理员维护面试官名称、开场白、身份原则、模型和音色。
- 模拟面试不保存输入或输出语音；只保存服务端收到的最终用户转写、面试官文字回复及其顺序。结束后以这份逐字稿生成结构化复盘，并在个人中心“模拟面试记录”中长期查看。
- 简历微调采用“AI 文字补丁 → 服务端核对原文片段 → 红减绿增对比 → 用户确认 → 新简历版本”的流程。模型只允许改写现有事实，缺失能力进入提醒而不能写进新简历；无有效变化时禁止创建重复版本。
- 当前新版本保存解析全文和版本血缘，不承诺还原原 PDF / Word 的视觉排版；原样式套版和导出属于后续独立能力。
- 首页和个人中心的职业形象复用统一 AI 服务地址和 API Key，只保留独立启停、图片模型、横图/方图尺寸以及三层可编辑提示词。服务端把已确认职业数据整理成脱敏摘要，再通过异步图片接口生成横图和方图；第一期不使用真人参考照片。双图均成功才自动成为当前版本，部分失败或全部失败时保留上一版。当前首页 Hero 是近方形槽位，页面读取方图并铺满；横图仍作为双图任务兼容资产生成和留存。完整边界见 [`个性化职业形象生成`](./career-image-generation.md)。

## 管理员配置规则

2026-08-19 运行态只读核验确认：职业形象区域已经只展示启停、模型、两种尺寸和三层提示词，并显示沿用统一凭证；旧的独立图片地址、独立图片 Key、轮询间隔和超时没有出现在该区域。页面能够读取现有配置，未复现旧的 `undefined.trim` 异常。该结论只证明当前已保存配置可渲染，不等于缺字段旧响应兼容、保存动作或活动任务恢复已经验收。

管理员可以在页面调整：

| 配置项 | 作用 | 修改方式 |
|---|---|---|
| 服务商名称 | 管理识别和调用记录归属 | 管理页面直接修改 |
| OpenAI 兼容基础地址 | Chat Completions 基础地址 | 仅允许服务端白名单中的 HTTPS 域名 |
| 模型 ID | 所有当前 AI 功能共用的模型 | 管理页面直接修改 |
| TTS 启停、模型与音色 | 能力路线摘要语音 | 管理页面直接修改 |
| 实时对话启停、模型与音色 | 目标岗位模拟面试的服务端实时代理 | 管理页面直接修改 |
| 图片启停、模型、两种尺寸和三层提示词 | 双图任务兼容横图、首页/个人中心方图 | 复用统一地址与 Key；当前首页近方形槽读取方图，横图场景仍保留，安全规则不可覆盖 |
| 面试官名称、开场白和身份原则 | 定义统一面试官基线；每场再动态注入 JD、简历和能力路线 | 管理页面直接修改 |
| API Key | 服务端鉴权密钥 | 新建时必填，后续留空表示保留原 Key |
| 启用状态 | 控制是否允许 AI 调用 | 停用后业务明确降级 |
| 腾讯云 OCR 状态 | 分别展示本月应用审计调用、账号配置的 1000 次共享免费资源额度、900 次应用保护阈值和 100 次安全预留 | 当前由后端 `.env` 维护，管理页面只读；它不是腾讯控制台实时账单，修改后须重启后端 |

管理员在页面保存的模型服务配置立即对后续调用生效，无需重启；腾讯 OCR 环境变量不属于网页保存范围，变更后须重启后端。管理页面提供模型连接测试，以及近 30 天总调用、成功/失败构成、多模态用量、能力类型和调用用户 Top 5 图表。不同能力的计费单位不能直接相加：文本统计 Token 并拆分输入/输出，语音统计字符，实时对话和视频统计秒，图像统计张数，OCR 统计 API 请求次数。

## 调用明细与配置操作记录

- “服务调用明细”统一展示 AI 与 OCR 调用。页面 / 功能点使用中文业务名称，原始英文 feature key 只保留为程序筛选值和悬浮辅助信息，不作为用户主文案。
- OCR 每个实际云端请求记为 `1 次请求`，不能显示为 Token，也不能把 14 个切片的一张长截图记作 1 次。
- 调用表格不保存 Prompt、原图、OCR 正文或模型回复；系统发起的 OCR 显示为“系统任务”，不会误写成普通用户。
- “配置操作记录”读取 `ai_configuration_audits`，展示管理员对模型服务的创建、更新和连接测试，不含 Key 内容。腾讯 OCR 由 `.env` 维护，当前不会伪造一条网页配置操作日志；其真实调用只进入服务调用明细。
- 2026-08-25 本机只读审计时，腾讯 OCR 应用日志共 146 次，其中 103 次成功；应用配置展示 1000 次共享免费资源额度，并在 900 次时软停止、预留 100 次。日志包含前期失败联调和真实切片调用，不能当作供应商账单；调用数、资源包消耗和后付费状态必须分别以实时接口与腾讯控制台为准。

## 收支账本问询的流式边界

收支守护的已确认账本问询当前使用 `POST /api/cashflow/ask/stream`。后端先由确定性程序生成统计、经济事实和工资守护上下文，再向当前文本模型发起上游 SSE 流式请求；对 Web 输出换行分隔 JSON（NDJSON），包含开始、上下文进度、回答增量、心跳、完成或错误事件。前端同源代理直接透传响应流并设置 `no-store, no-transform`，不会先把整段回答缓存完再返回。

浏览器逐事件追加答案，并用 `SafeMarkdown` 渲染受限 Markdown。组件只支持标题、列表、引用、强调、行内代码、代码块和安全链接等必要语法；不执行 HTML、脚本或事件属性。前端关闭、切换会话或取消请求时会中止读取，上游流也会收到取消信号。服务端只有在得到完整、满足契约的最终结果后才保存问答回合和引用；中途中断不会把半段文字伪装成正式结论。流式失败时页面保留程序已经算出的事实、显示明确错误并允许重试，不影响账本、图表和候选核对。

代码 Alembic head `20260825_0057` 为收支问询增加请求级幂等：浏览器为一次逻辑问询生成 `request_id`，服务端持久化请求指纹，并通过 `(user_id, request_id)` 唯一约束防止同一用户的断线重试重复创建回合。指纹相同时重用已保存回答，同一标识对应不同请求内容时返回 409，不再次调用模型。`0057` 不新增表，但当前本机 MySQL `zhihu` 仍在 `20260825_0056`，因此持久化幂等保证只能在迁移部署并完成运行核对后宣称生效；本轮未经新授权不迁移本机或正式业务库。

这项流式能力只适用于当前收支账本问询，不代表简历解析、Offer 分析、路线生成、图片生成或其他 AI 接口均已改为流式。真实回答质量、极长会话、网络中断恢复和手机端长回答仍需持续验收。

## 语音延迟边界

当前稳定链路是“结构化路线落库 → 摘要 TTS → 边下载边播放 → 缓存”，用户能看到生成状态，切页返回后任务不丢失。它已减少重复生成的等待，但还不是“文本 Token 刚产生就同步朗读”的端到端流式链路。后续若实现该效果，需要同时将文本生成改为流式输出，在服务端分句，串联 TTS SSE/WebSocket，并由服务端代理长期密钥。

## 密钥和数据边界

- 管理员配置保存在 `zhihu.ai_provider_settings`，API Key 使用 Fernet 加密，完整值不进入接口响应、前端状态或 Git。
- `AI_CONFIG_ENCRYPTION_KEY` 是生产环境推荐的独立加密根密钥；未配置时使用 `JWT_SECRET` 派生本地兼容密钥。
- `zhihu.ai_configuration_audits` 记录修改人、服务商、地址、文本/TTS/实时对话模型、启停和是否更换 Key，不记录 Key 内容。
- `zhihu.ai_invocation_logs` 只记录用户或系统主体、中文映射后的功能点、能力类型（文本/语音/图像/视频/实时对话）、模型、成功失败、耗时和用量。文本用量为 Token，语音用量为字符数，腾讯 OCR 用量为请求次数；不记录 Prompt、简历、Offer、音频正文、OCR 图片/原文或模型回答。
- `zhihu.career_image_generations` 保存图片任务、脱敏摘要、提示词哈希、模型、尺寸、版本和私有图片二进制。图片调用日志不保存 Prompt、摘要或图片内容；供应商图片地址通过公网 HTTPS 校验后才允许下载。
- `zhihu.mock_interview_sessions` 是用户产品记录，不是调用日志：保存目标岗位/简历引用、场次状态、结构化逐字稿、摘要和复盘；不保存麦克风音频或面试官音频。实时调用日志只保存用户、功能点、时长和结果状态。
- 原始简历文件不发送给 AI；发送的是服务端从文件提取的文字。用户可在个人中心查看实际解析全文和结构化结果。
- `.env` 中的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 仅作为尚未建立管理员配置时的兼容回退；一旦数据库存在配置，就以管理员配置为准。
- 允许域名由服务端 `AI_ALLOWED_BASE_HOSTS` 控制，防止管理员测试功能被用于请求任意内网地址。

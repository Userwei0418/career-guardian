# 采集解析规则恢复与自愈

## 目标与安全边界

招聘站点改版后，选择器、字段路径、详情展开方式或分页方式可能失效。职护可以调用管理员配置的 AI 生成修复候选，但模型不直接改写运行代码、不直接覆盖生效规则，也不能绕过 Raw、语义清洗和质量门写入产品主库。

当前自动修复对象严格限制为声明式策略：岗位卡片选择器、详情选择器、加载更多按钮、下一页按钮、滚动参数和运行上限。候选 JSON 不允许包含 JavaScript、Python、函数、Cookie、Token、密码或任意请求头。无法由声明式策略安全表达的站点必须转人工开发适配器，不把模型输出当作可执行代码。

## 稳定基线已经具备

1. **失败分类**：运行异常会归类为页面规则变化、站点不可达、限流、访问封禁、需要会话、临时网络异常、质量处理异常或未知异常。
2. **退避与阻断**：临时错误按连续失败次数指数退避；限流进入较长冷却；验证码、403 或登录要求会阻断来源，管理员不能在冷却期重复启动任务。
3. **受限页面证据**：AI 修复只读取公开页面的标题、URL、截断后的重复 DOM 结构和最近失败签名，不保存完整页面，不读取 Cookie、存储、认证头或表单隐私数据。
4. **受限候选**：市场数据服务只接受固定 JSON，并校验字段白名单、选择器长度、分页模式和数值上限后才保存；管理员也可人工维护声明式候选。
5. **安全回放与 Canary**：候选固定使用无头浏览器，最多读取 20 条、执行 3 轮；必须发现岗位且详情完整率达到 80%，才能进入 `canary_passed`。
6. **人工启用**：管理员在后台查看故障、候选和回放指标，确认后发布为新的 `collection_strategy_versions` 生效版本。
7. **回滚**：新版本异常时可从同一候选记录回滚到上一生效版本。修复审批只解除“规则故障”阻断，不伪造一次采集成功；下一次真实成功后才更新渠道成功时间。

正常成功任务同样会沉淀“实际发生了什么”，而不是只保存预期配置：列表选择器、分页/加载动作、详情模式和实际命中的详情选择器会组成策略版本。未拿到详情时只记录 `missing` 诊断证据并进入质量门或隔离流程，不会把“缺失”发布为下一次继续复用的详情策略。

稳定的人工治理状态为：

```text
candidate -> canary_passed -> approved -> rolled_back
          \-> replay_failed --重新调整后再次回放
```

## 自动生成链路

“解析规则故障”已经自动接到管理员配置的 AI：

```text
解析规则故障
  -> ai_pending
  -> ai_generating
  -> candidate / ai_failed（有限重试）
  -> 受限回放
  -> canary_passed
  -> 人工 approved
  -> rolled_back（异常时）
```

系统会幂等补建历史解析故障，按“渠道 + 归一化故障签名”复用活动候选；重复扫描同一失败任务不会增加故障次数或重复写事件。Worker 领取候选时持有带过期时间的租约，只有当前 Worker 可完成或记录失败；租约过期可被其他 Worker 回收，生成失败按固定上限和下次重试时间有限重试。

AI 调用日志的功能点明确为“采集解析规则自动修复”，记录系统主体、时间、供应商/模型、文本模态、成功失败、耗时、Token/用量和可得成本；供应商未返回成本时保持空值并明确展示。日志不得记录完整 DOM、Prompt、JD 原文、密钥或模型完整响应。

管理员页面展示 `ai_pending`、`ai_generating`、`ai_failed`、`candidate`、`replay_failed`、`canary_passed`、`approved` 和 `rolled_back`。生成成功会清除上一轮重试错误，避免已就绪候选仍显示过期失败信息。安全回放属于长操作，业务网关只为该接口使用 180 秒超时；普通管理请求继续使用短超时。

2026-08-17 真实验收中，58 同城解析失败自动生成候选，回放发现 0 个岗位并停留在 `replay_failed`，没有自动启用；360 单次可见采集留下 `requested=visible`、`actual=visible` 证据并启动非 headless Playwright Chromium。三安光电“IE工程师”的来源展开详情与 Raw/Core 事实一致，H&H 缺详情记录因明确原因留在 Raw 隔离区。

## 健康与恢复策略

渠道健康状态保存在 `market_raw.source_operational_states`，不是页面临时状态：

| 故障 | 系统动作 | 管理员看到的建议 |
|---|---|---|
| 选择器/解析规则失效 | 标记 degraded，允许创建修复候选 | 回放、Canary、审批后发布新策略 |
| DNS、连接、短时超时 | 指数退避 | 到达 `next_retry_at` 后重试 |
| 429/限流 | 延长冷却 | 降低频率，避免立即重复执行 |
| 验证码、403、访问封禁 | 阻断并告警 | 人工核对条款与网络策略 |
| 登录/Session 要求 | 阻断并告警 | 配置服务端受控 Session 引用 |
| 质量门或语义清洗失败 | 标记 degraded | 查看 Raw 处理轨迹，不改抓取规则掩盖问题 |

渠道只保存不敏感的网络策略引用。`proxy_pool_id` 和 `session_profile_id` 是服务端资源的别名；代理地址、认证信息、Cookie 和浏览器 storage state 由部署环境解析，不写数据库、不返回前端、不进入审计摘要。系统不会通过未授权代理绕过站点条款。

## 管理后台验收

管理员在“数据采集”中可以完成以下操作：

- 查看渠道默认浏览器模式，并在单次公司采集时覆盖为“渠道默认 / 全部无头 / 全部可见”；
- 查看最近成功、最近失败、连续失败次数、冷却截止时间、告警状态和系统恢复建议；
- 查看增量检查点、近期岗位标识、内容指纹以及距离下一次全量核对还有多少次；
- 查看可信发布时间高水位和重叠窗口；只有连续多个完整日期批次都早于边界才允许停止，任何无日期批次都会重置该停止判定；
- 配置直连、受控代理、受控 Session 或二者组合，但只能提交服务端不透明引用；
- 查看 AI/人工修复候选及其生成状态，执行受限回放、审批启用和版本回滚；
- 从采集任务明细追溯 Raw 新增、重复、程序化处理、AI 语义处理、质量门晋级或隔离原因。

普通用户页面不展示采集规则、质量门或系统恢复术语，只展示已经通过质量门且可追溯的岗位事实。

## 验收阈值

- 修复候选发现岗位数大于 0，Canary 最多 20 条、3 轮。
- 详情完整率不低于 80%；无职责、要求或足够 JD 正文的数据不能进入 Core。
- 详情链接仍须属于渠道允许域名，企业和渠道身份不能由模型改写。
- 规则启用、回滚、失败分类、冷却与告警均有数据库记录。
- AI 不可用时，管理员仍可编辑声明式候选并完成同一回放和审批流程；采集与硬质量门不依赖 AI 才能运行。

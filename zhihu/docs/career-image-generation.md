# 个性化职业形象生成

- 生效日期：2026-08-19
- 用户入口：首页职业形象卡片、个人中心职业形象
- 管理入口：`管理后台 → AI 配置 → 职业形象图片服务`
- 代码入口：`app/services/career_image_service.py`、`app/api/routes/career_images.py`、`CareerImageExperience.tsx`
- 数据迁移：`20260819_0019`

## 产品范围

第一期根据用户已经确认的职业数据生成两张视觉风格一致的匿名职业旅程插画：

- 首页横图：默认 `1536x864`，人物位于右侧，左侧保留界面文字安全区。
- 个人中心方图：默认 `1024x1024`，适合圆角卡片展示。

第一期不上传或使用真人参考照片，不生成写实人脸，不推断年龄、性别、民族、健康、宗教等敏感属性。图片只表达职业方向、技能组合、成长重点和职业阶段，不承担简历事实证明或招聘判断。

## 数据来源与脱敏摘要

服务端只读取当前用户已经保存并确认的数据：

1. 用户档案中的职业阶段、目标岗位、技能和职业偏好。
2. 当前有效简历的结构化档案、已抽取技能和亮点。
3. 最近的目标岗位快照和岗位—简历分析结果。
4. 已完成模拟面试的结构化复盘结论。

不会把原始简历文件、简历全文、模拟面试逐字稿、姓名、联系方式、网址、证件号或可识别的公司/学校名称发送给图片模型。服务端先生成受限的 `profile_summary`，再执行以下处理：

- 清除邮箱、手机号、网址和长数字标识。
- 将可识别组织名称替换为“某组织”。
- 对岗位、技能、优势、成长重点和偏好分别限制数量与单项长度。
- 只保留最近少量目标、分析和面试复盘；输入为空时拒绝生成。

摘要与来源版本共同计算 `source_fingerprint`。档案、简历、目标岗位或复盘发生变化时，当前图片会标记为“资料已更新”，用户可选择重新生成；旧图片不会自动删除。

## 生成与状态机

用户点击生成后，后端为同一版本并行提交横图和方图两个异步任务：

```text
用户确认生成
  → 构建脱敏职业摘要与两套构图提示词
  → POST /v1/image/async
  → 保存横图/方图 task_id
  → 前端按管理员配置的间隔轮询职护后端
  → GET /v1/image/pending
  → 服务端校验并下载生成图片
  → 两张均成功后设为当前版本
```

版本总状态包括：

- `queued`：本地版本已创建，准备提交。
- `submitted`：至少一个图片任务已经提交。
- `generating`：图片供应商仍在处理。
- `completed`：横图和方图均已完成，可设为当前版本。
- `partial`：只有一个尺寸成功；保留证据但不替换当前版本。
- `failed`：两个尺寸均失败。

同一用户只允许一个活动任务。MySQL 用户行锁保护“检查活动任务 + 分配版本号”，避免重复点击生成相同版本号。仅 `completed` 版本可手工切换为当前版本；新任务部分失败或全部失败时，上一版当前图片继续展示。

## 存储、访问与版本留存

- 任务、提示词哈希、脱敏摘要、模型、尺寸、供应商任务号、状态、错误摘要和版本号保存在 `zhihu.career_image_generations`。
- 横图和方图二进制使用 MySQL `MEDIUMBLOB` 保存，不写入公开静态目录。
- 图片只能通过当前用户鉴权接口读取，响应使用 `Cache-Control: private` 和 `nosniff`。
- 管理员可查看任务元数据、用户、供应商、状态和错误摘要，但接口不返回图片服务密钥或原始职业材料。
- 版本默认长期保留，用户可在个人中心查看历史并切换已完成版本。

## 管理员配置与调用日志

管理员可以独立配置图片能力，不受文本模型启停状态影响：

| 配置项 | 默认值/说明 |
|---|---|
| 图片服务基础地址 | `https://api.senseaudio.cn/v1` |
| 图片模型 | `senseaudio-image-2.0-260319` |
| 首页横图尺寸 | `1536x864` |
| 个人中心方图尺寸 | `1024x1024` |
| 轮询间隔 | 3 秒，接口约束 1～30 秒 |
| 任务超时 | 240 秒 |
| API Key | 服务端加密保存，页面只显示掩码 |

服务端调用 SenseAudio `POST /image/async` 提交任务，通过 `GET /image/pending` 查询结果。供应商返回的图片地址在下载前必须满足 HTTPS、公网 DNS 和公网 IP 约束，禁止访问本机、内网、链路本地和其他保留地址；下载大小默认不超过 16 MiB。

每次提交和轮询都写入统一 `ai_invocation_logs`：记录用户、功能点、能力类型 `image`、模型、成功/失败、耗时和图片数量，不记录 Prompt、脱敏摘要、图片内容或 API Key。管理员在 AI 配置页可同时查看配置和职业形象任务列表。

## 失败回退

- 图片服务未配置：用户端展示统一的本地抽象插画，并提示管理员尚未启用服务。
- 用户职业信息不足：禁止提交任务，提示先确认目标岗位或技能。
- 提交、轮询或下载失败：记录短错误码和调用日志，不向页面泄露供应商响应正文。
- 单张失败：任务标记 `partial`，已完成图片作为版本证据保留，但不自动成为当前版本。
- 全部失败：任务标记 `failed`，上一版当前图片继续有效。
- 职业数据变化：当前版本标记 `is_stale`，不自动删除或覆盖。

## 用户 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/career-images/current` | 当前版本、活动任务、是否可生成和轮询间隔 |
| POST | `/api/career-images/generate` | 创建双尺寸异步生成任务 |
| GET | `/api/career-images/versions` | 分页读取本人的版本历史 |
| GET | `/api/career-images/generations/{id}` | 刷新本人任务状态 |
| POST | `/api/career-images/generations/{id}/activate` | 切换已完成历史版本 |
| GET | `/api/career-images/generations/{id}/asset/{variant}` | 鉴权读取横图或方图 |

管理员任务列表使用 `/api/admin/ai/career-images`，支持按状态分页筛选。

## 验证要求

- 运行数据库和测试数据库都只使用 MySQL。
- 涉及数据库的测试必须显式设置 `CAREER_GUARDIAN_TEST_DATABASE_URL`，且库名必须包含 `test`；正式 `zhihu`、`market_raw` 和 `pin_legacy_staging` 会被测试保护器拒绝。
- 服务测试覆盖脱敏摘要、提示词边界、供应商地址安全、双图完成、历史版本切换和部分失败保留旧当前版本。
- 前端验收覆盖：首页横图、个人中心方图、活动状态、失败回退、历史版本和管理员配置/日志。
- 真实供应商验收会产生外部调用和可能的费用，应在管理员已配置独立图片 Key 并明确授权后执行；日常 CI 使用受控替身，不调用正式图片服务。

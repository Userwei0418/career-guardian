## 产品范围

第一期后端仍根据用户已经确认的职业数据生成两张视觉风格一致的匿名职业旅程插画。当前页面遵循“卡片比例由产品布局确定，图片资产适配卡片”的规则：

- 首页主视觉和个人中心当前都读取 `1024x1024` 方图。首页右侧在桌面与手机均是近方形槽位，只做少量居中裁切，不再把 16:9 图片悬在卡片上半部。
- `1536x864` 横图仍是双图任务的必生成子任务，参与版本 `completed` 判定，并继续入库、由鉴权接口读取；当前分栏 Hero 不展示它。横图生成链路尚未清理，不能描述成已经取消或可忽略的可选资产。

第一期不上传或使用真人参考照片，不生成写实人脸，不推断年龄、性别、民族、健康、宗教等敏感属性。图片只表达职业方向、技能组合、成长重点和职业阶段，不承担简历事实证明或招聘判断。

## 数据来源与脱敏摘要

服务端只读取当前用户已经保存并确认的数据：

1. 用户档案中的职业阶段、目标岗位、技能和职业偏好。
2. 当前有效简历的结构化档案、已抽取技能和亮点。
3. 最近的目标岗位快照和岗位—简历分析结果。
4. 已完成模拟面试的结构化复盘结论。

不会把原始简历文件、简历全文、模拟面试逐字稿、姓名、联系方式、网址、证件号或可识别的公司/学校名称发送给图片模型。服务端先生成受限的 `profile_summary`，再执行以下处理：

- 清除邮箱、手机号、网址和长数字标识。
- 将可识别组织名称替换为“某组织”。
- 对岗位、技能、优势、成长重点和偏好分别限制数量与单项长度。
- 只保留最近少量目标、分析和面试复盘；输入为空时拒绝生成。

摘要与来源版本共同计算 `source_fingerprint`。档案、简历、目标岗位或复盘发生变化时，当前图片会标记为“资料已更新”，用户可选择重新生成；旧图片不会自动删除。

## 生成与状态机

用户点击生成后，后端为同一版本并行提交横图和方图两个异步任务：

```text
用户确认生成
  → 构建脱敏职业摘要与两套构图提示词
  → POST /v1/image/async
  → 保存横图/方图 task_id
  → 前端按管理员配置的间隔轮询职护后端
  → GET /v1/image/pending
  → 服务端校验并下载生成图片
  → 两张均成功后设为当前版本
```

版本总状态包括：

- `queued`：本地版本已创建，准备提交。
- `submitted`：至少一个图片任务已经提交。
- `generating`：图片供应商仍在处理。
- `completed`：横图和方图均已完成，可设为当前版本。
- `partial`：只有一个尺寸成功；保留证据但不替换当前版本。
- `failed`：两个尺寸均失败。

目标规则是同一用户只允许一个仍可能从供应商回收结果的任务。现有 MySQL 用户行锁能够保护“检查 active 状态 + 分配版本号”，避免普通并发双击生成相同版本号；但本地已经写成 `generation_timeout`、供应商仍可能完成的记录尚未完全纳入创建接口的幂等判断，仍需修复和验证。仅 `completed` 版本可手工切换为当前版本；新任务部分失败或全部失败时，上一版当前图片继续展示。

任务状态设计上不依赖浏览器组件内存。当前 `GET /api/career-images/current` 会从 MySQL 找回最新 active 任务，或尝试恢复最新的全量 `generation_timeout` 失败任务，再查询供应商；既有两个版本已经通过保留的 `task_id` 回收到晚到结果。当前没有活动任务可用于真实刷新/切路由/重启验收，而且部分超时和创建接口幂等仍有上述缺口，所以不能据此断言所有页面重建场景都已可靠恢复。

## 存储、访问与版本留存

- 任务、提示词哈希、脱敏摘要、模型、尺寸、供应商任务号、状态、错误摘要和版本号保存在 `zhihu.career_image_generations`。
- 横图和方图二进制使用 MySQL `MEDIUMBLOB` 保存，不写入公开静态目录。
- 图片只能通过当前用户鉴权接口读取，响应使用 `Cache-Control: private` 和 `nosniff`。
- 管理员可查看任务元数据、用户、供应商、状态和错误摘要，但接口不返回图片服务密钥或原始职业材料。
- 版本默认长期保留，用户可在个人中心查看历史并切换已完成版本。

## 管理员配置与调用日志

职业形象保留自己的启停开关，但图片调用与文本能力复用同一套服务端地址和 API Key。管理员页面只暴露与视觉产物直接相关的参数：

| 配置项 | 默认值/说明 |
|---|---|
| 是否启用 | 用户是否可以主动生成职业形象 |
| 图片模型 | `senseaudio-image-2.0-260319` |
| 兼容横图尺寸 | `1536x864`；双图任务仍生成，当前首页近方形 Hero 不读取 |
| 首页/个人中心方图尺寸 | `1024x1024` |
| 通用风格提示词 | 两种图片共同使用的美术风格、色彩、材质和人物表达 |
| 兼容横图场景提示词 | 横向构图、文字安全区和兼容场景要求；当前首页近方形 Hero 不读取该资产 |
| 首页/个人中心方图场景提示词 | 方形构图、主体层级和近方形卡片裁切要求 |

提示词由四层合成：管理员配置的通用风格、当前尺寸的场景提示词、用户脱敏职业摘要、服务端固定的隐私与安全约束。管理员提示词可以改变画面语言和构图，不能移除“不出现文字和标志、不生成可识别人脸、不推断敏感属性、不泄露组织名称”等固定约束。

轮询间隔、任务超时和下载上限属于服务内部运行参数，不在职业形象管理区域重复配置。当前内部任务截止时间为 15 分钟；到期时会先查询一次供应商状态。现有真实任务耗时已经超过 15 分钟，因此本地截止时间只能作为需要继续对账的运行信号，不能当作供应商最终失败事实或恢复生成按钮的充分条件。服务端调用 SenseAudio `POST /image/async` 提交任务，通过 `GET /image/pending` 查询结果。供应商返回的图片地址在下载前必须满足 HTTPS、公网 DNS 和公网 IP 约束，禁止访问本机、内网、链路本地和其他保留地址；下载大小默认不超过 16 MiB。

每次提交和轮询都写入统一 `ai_invocation_logs`：记录用户、功能点、能力类型 `image`、模型、成功/失败、耗时和图片数量，不记录 Prompt、脱敏摘要、图片内容或 API Key。管理员在服务配置页可同时查看配置和职业形象任务列表。

## 失败回退

- 图片服务未配置：用户端展示统一的本地抽象插画，并提示管理员尚未启用服务。
- 用户职业信息不足：禁止提交任务，提示先确认目标岗位或技能。
- 提交、轮询或下载失败：记录短错误码和调用日志，不向页面泄露供应商响应正文；本地 `generation_timeout` 保留供应商任务号，后续状态读取可自动对账晚到结果。
- 单张失败：任务标记 `partial`，已完成图片作为版本证据保留，但不自动成为当前版本。
- 全部失败：任务标记 `failed`，上一版当前图片继续有效。
- 职业数据变化：当前版本标记 `is_stale`，不自动删除或覆盖。

## 用户 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/career-images/current` | 当前版本、活动任务、是否可生成和轮询间隔 |
| POST | `/api/career-images/generate` | 创建双尺寸异步生成任务 |
| GET | `/api/career-images/versions` | 分页读取本人的版本历史 |
| GET | `/api/career-images/generations/{id}` | 刷新本人任务状态 |
| POST | `/api/career-images/generations/{id}/activate` | 切换已完成历史版本 |
| GET | `/api/career-images/generations/{id}/asset/{variant}` | 鉴权读取横图或方图 |

管理员任务列表使用 `/api/admin/ai/career-images`，支持按状态分页筛选。

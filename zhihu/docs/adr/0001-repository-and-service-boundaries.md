# ADR-0001：仓库与服务边界

- 状态：Accepted
- 日期：2026-08-15
- 对应功能点：FP-00

## 决策

使用一个私有 GitHub monorepo 维护职护 Web、职护业务 API、市场数据服务和产品文档。历史采集项目只在能力内化阶段作为来源，不作为长期仓库组成或运行时依赖。

现有 `zhihu/zhihu-frontend` 内层 Git 仓库退出独立版本管理，其 Git 元数据在本机 `.legacy-git/` 中保留可恢复副本；后续所有代码从工作区根仓库统一提交。该操作不删除前端源码和用户已有修改。

服务边界固定为：

| 服务 | 本地端口 | 边界 |
|---|---:|---|
| 职护 Web | 3000 | 用户界面，只调用职护业务 API |
| 职护业务 API | 8000 | 用户、材料、职业事件和守护结论 |
| 市场洞察 API | 8100 | 后续建设的内部只读市场事实接口 |
| 采集任务管理 | 8101 | 后续建设的受控管理接口，不向浏览器开放 |
| MySQL | 3306 | 本地或受控网络数据库 |

## 数据边界

- Offer、合同、工资条和个人档案只进入职护业务数据域。
- 公共招聘数据进入市场数据域，并按 Raw、Core、Insight 分层。
- 仓库外历史数据库导入物只允许经过受控流程进入隔离 staging 做质量审计，不进入 Git，也不直接供职护查询。
- 职护 Web 不连接采集数据库或调用采集写接口。

## 原因

单仓库便于在一个变更中完成前端、API、数据契约和验收证据，同时保留清晰的服务和数据权限边界。历史参考项目的必要能力应内化为职护自有代码、版本化资产或最小测试夹具，而不是把完整项目长期并入产品仓库。

## 约束

- 不在未授权情况下上传真实用户材料、密钥或数据库备份。
- 不把 fixture、mock 或历史快照标记为实时市场数据。
- 涉及生产部署、真实数据迁移和外部采集前仍需单独确认。

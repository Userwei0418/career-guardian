# ADR-002：市场数据生产与职护业务边界

- 状态：Accepted
- 日期：2026-08-15
- 范围：职护 V2 业务 API、市场数据服务与 Pin 历史能力

## 背景

`Pin` 包含招聘数据获取、代理、解析和历史存储能力，但它的数据模型、字段范围、运行依赖和凭据处理方式不能直接成为职护在线业务的数据边界。职护需要的不是原始岗位复制，而是能回答用户问题、可追溯、可判断时效和质量的最小市场事实。

## 决策

1. `Pin` 保留为历史实现和数据获取能力的参考源，不被职护业务 API 直接 import、直接连库或在用户请求中启动。
2. 市场数据生产链路独立为 Raw、Core、Insight 三层：先保留原始证据，再清洗为标准岗位和企业，最后生成只读市场洞察。
3. 职护业务 API 只消费通过质量校验的 Insight，不读 Raw、staging 或采集运行表。
4. 市场洞察响应必须包含 `availability`、样本量、观测时间范围、方法版本、质量等级与来源引用；不可用时返回结构化状态，不用 mock 值填充。
5. 用户 Offer、合同、工资条及衍生结论属于 Guardian DB；公共岗位样本属于市场数据服务。两者只通过不含用户私密材料的标准查询条件和快照 ID 关联。
6. 采集凭据只存放在 Worker 的服务端密密管理中，不进入仓库、浏览器、职护数据库或运行日志。

## 结果

- FP-01 只定义市场洞察契约和固定样本，不宣称已获得真实市场数据。
- FP-02 负责新建数据源注册、采集任务和 Raw 记录，并对 Pin 备份进行隔离质量审计。
- FP-03 和 FP-04 分别负责标准化与市场洞察；下游守护功能不能越过这些验收依赖。
- 短期内会增加契约和数据管道的实现工作，但可以防止历史库、未清洗字段和采集故障直接泄漏到用户结论中。

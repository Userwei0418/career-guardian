# 职护 Career Guardian

职护是面向应届生和职场新人的职业守护产品，围绕机会、决策、权益、收入和成长五个领域，建立从真实岗位到 Offer、合同和首月工资核对的连续证据链。

## 仓库结构

- `zhihu/zhihu-frontend`：职护 Web。
- `zhihu/zhihu-backend`：用户、材料、职业事件与守护结论 API。
- `Pin`：现有招聘数据获取能力的参考实现和历史迁移来源；不直接作为职护在线业务接口。
- `zhihu/docx`：产品蓝图和按功能点组织的开发计划。
- `zhihu/docs`：架构决策、开发和验收记录。

## 当前开发状态

`FP-00 可复现与安全基线` 已验收。V2.1 已完成五领域导航、统一职业事件模型和 MySQL 主库收口。机会守护目前包含市场全景、岗位搜索/详情、简历版本，以及用户主动确认后执行的“JD + 指定简历”AI 辅助分析；分析会落为可追溯证据、结论和待本人确认的行动草稿。

原 FP 编号仅用于追溯历史实现与验收记录，不再作为串行解锁门禁。执行方式以 [`职护 V2 开发计划`](./zhihu/docx/职护%20V2%20开发计划.md) 为准，当前证据见 [`PROGRESS.md`](./zhihu/progress/PROGRESS.md)。

运行时统一使用一个 MySQL 实例：`zhihu` 是产品主库，用户数据与清洗后的市场事实（`market_*` 表）都在其中；`pin_legacy_staging` 和 `market_raw` 仅隔离历史迁移证据与采集原文。SQLite 只用于自动化测试。

数据库的唯一当前基线、合法数据流和存量行数口径见 [`职护当前数据库结构`](./zhihu/docs/data/current-database-architecture.md)。独立 `market_core` 数据库已经完成迁移并删除，后续不得重新创建。

所有岗位进入 `zhihu.market_jobs` 前必须通过同一个版本化质量门；Pin 历史数据和以后新抓取的 Raw 数据使用同一套来源、身份、薪资、时效、质量和去重规则。

管理员可在“管理后台 → 数据准入”查看并调整准入硬条件、阈值和评分权重。修改采用草稿、影响预检、发布三步，已发布版本保留审计记录；质量门不作为用户页面概念展示。机会守护默认每页展示 8 条岗位，支持切换到 12/20 条，并可按职务、公司、城市、专业和招聘类型组合搜索。

本仓库不提交 `.env`、用户上传材料、运行日志、构建依赖或 `Pin/db/backup.sql`。本地开发和验证方式见 [`开发基线`](./zhihu/docs/development.md)。

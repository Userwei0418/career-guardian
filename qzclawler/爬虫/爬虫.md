# 爬虫
> **爬虫是什么 → 怎么抓 → 用什么方式抓 → 抓下来怎么处理 → 怎么稳定运行 → 怎么形成完整系统**

## 第一层：原理层

先回答这些最基础的问题：

*   爬虫到底是什么？
*   浏览器打开网页时发生了什么？
*   HTML、接口、JSON、DOM 分别是什么？
*   为什么有些网页 `requests` 能抓，有些必须用 Playwright？
*   为什么项目里会出现“页面 DOM 抓取、API 抓取、on\_response 监听”这些不同方式？
*   为什么职位列表可以走接口，职位详情却还要打开页面？
*   什么是反爬？什么是代理？什么是断点续跑？

四重采集通道定义为：

1.  **静态页面采集**：直接请求网页 HTML，再从 HTML 里提取内容。
2.  **动态页面采集**：用 Playwright 像真人一样打开网页、点击、滚动、翻页。
3.  **API 直连采集**：直接请求网站接口，拿 JSON 数据。
4.  **浏览器响应监听采集**：页面正常打开，但我们监听它背后的接口响应，也就是 `on_response`。

## 第二层：基础操作层

理论讲清楚后，再进入“一个动作能得到什么效果”。

比如：

| 基础操作 | 能得到什么 |
| --- | --- |
| `requests.get(url)` | 拿到网页源码或接口 JSON |
| `BeautifulSoup` / `lxml` | 从 HTML 里提取标题、链接、正文 |
| `json.loads()` | 解析接口返回的结构化数据 |
| Playwright `page.goto()` | 打开动态网页 |
| Playwright `page.click()` | 模拟点击筛选项、分页、加载更多 |
| Playwright `page.locator()` | 定位页面元素 |
| `page.on("response")` | 监听网页背后的接口返回 |
| 文件写入 JSON | 保存中间结果，便于排查和重跑 |
| 去重判断 | 避免重复抓同一个职位 |
| 状态文件 | 支持断点续跑 |

用小例子讲清楚：

打开网页  
→ 找到职位列表  
→ 提取职位标题和链接  
→ 打开详情页  
→ 提取职位描述  
→ 保存成 JSON

> 真实项目就是把这些基础动作不断组合、封装、增强。

## 第三层：架构层
